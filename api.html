Rhys Airways Booking API

Search live schedules and create bookings from your own tools — a desktop widget, a Discord bot, or the in-game self-service kiosk.

Demo environment. The console below runs entirely in your browser: your key is checked locally with SHA-256 and bookings are simulated client-side. Wire this contract to a real backend before production — see README.md in the repo for the reference Cloudflare/AWS blueprint. Never put production API keys in front-end code.

Authentication

Send your key as a Bearer token. Keys are issued by Rhys Airways Operations and are prefixed rhys_live_.

Authorization: Bearer rhys_live_<your-key>
Content-Type: application/json

Endpoints

GET /v1/flights?route=SYD → upcoming departures for a route GET /v1/airline → airline, hub, destinations, fleet POST /v1/bookings → create a booking { "route": "SYD", "date": "2026-11-20", "passengers": 2, "cabin": "economy", "passenger": { "name": "Jordan Smith", "email": "you@example.com" } } GET /v1/bookings/{pnr} → booking status DELETE /v1/bookings/{pnr} → cancel (full refund in the 24h window)

Example — create a booking

curl -X POST https://api.rhysairways.example.com/v1/bookings \
  -H "Authorization: Bearer $RHYS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"route":"LHR","date":"2026-12-01","passengers":1,"cabin":"economy",
       "passenger":{"name":"Jordan Smith","email":"you@example.com"}}'

Rate limits & errors

60 requests / minute per key · burst 20 429 rate_limited — slow down 401 invalid_api_key — check your Authorization header 404 route_not_found — unknown route code 422 validation — missing/invalid fields (date, pax, cabin)
